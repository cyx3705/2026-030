## 取舍

- **只做「一次调用」，不做会话。** 上下文由调用方持有并逐次回传；会随热重载消失的会话缓存只会让调用方以为不必管上下文。
  不做提示词工程、结果解析、自动重试（重试策略属于调用方，模块替它决定会掩盖计费与限流）。
- **联网搜索由模块代模型执行。** 搜不搜、搜什么由模型决定；`web` 默认关，打开后费用是 token 加按次计费的博查搜索两份。
  每次调用最多真搜 5 次，再宽限 2 轮仍只要工具就判卡住失败。单次搜索失败只告诉模型；博查没配密钥整次失败——那是配置问题，不该让模型装作查过。
- **调用过程归 Apollo 写进控制台。** 写 `CommandContext.Progress`，经总线的嵌套调用也有这条通道；消费方不要再从回执复述搜索与答复。
  粒度是「轮」不是逐字（`stream=false`）：控制台按行渲染，几路并发逐字刷屏反而读不清。
- **chat 指令不声明 Readonly。** 不写本机，但每次都是计费外网请求；标只读等于告诉「只读即安全」的消费面随便调。
- **密钥参数名必须叫 `token`、位置 0。** 总线按参数名判定敏感值，改成 `apikey` 会让回显、历史、结果脱敏同时静默失效（测试钉住）。
- **图片走识图供应商（0.5.0）。** 带 `images=` 且省略 `provider=` 时用识图供应商（内置 `qwen` 通义千问，`apollo.provider.use <名> vision=true` 可改），不用默认供应商。
  原因见下「真机才知道的」第一条。只收本机文件路径、不收网址（不替调用方多开出网口子）；超限直接拒、不偷偷缩图——缩到多小还看得清只有调用方知道。

## 真机才知道的

- **DeepSeek 收图片但看不到**（2026-10-06 实测 `deepseek-flash` 返回空、`deepseek-v4-pro` 回答「无法查看图片」，都是 HTTP 200）。
  不报错的「看不到」比报错危险：模型会照着文字瞎编，所以带图请求必须换供应商，而不是靠服务端拒绝。
- 服务端会把 `deepseek-chat` 解析成当次主推模型（实调返回 `deepseek-v4-flash`），回执按服务端返回的名字报告；要固定模型就显式传 `model=`。
- DeepSeek 思考模式下带工具的后续请求必须把助手消息（含 `reasoning_content` 与 `tool_calls`）**原样**回放，自己挑字段重建就是 400。
- 博查在 HTTP 200 里也会返回业务错误（`code != 200`），按远端失败处理，不当「没有结果」。

## 工程约定

- 发版改三处版本号：`HistoryApolloVersion.props`、`b-Code/HistoryApollo/module.manifest.json`、`project.manifest.json`；`Test-ProjectContract.ps1` 核对一致。
- 数据目录由宿主给（`ModuleData\HistoryApollo`）：`providers.json` 是供应商与密钥库、`logs\` 是日志；独立于包槽位，热装不抹密钥。
  环境变量优先：`APOLLO_<供应商>_KEY` → `<供应商>_API_KEY` → 库文件，来源在 `apollo.provider.list` 里报告。
- 新增一家 OpenAI 兼容供应商：`ProviderStore.Builtin` 加一行，或本机 `apollo.provider.config provider=<名> baseurl=<地址>`。
- **密钥绝不入库**：合同检查扫全仓拒绝 `sk-` 后接 32 位以上十六进制；测试夹具写 `sk-fake…`、`sk-test`。
- 项目合同检查自带规则（共享的 `OneHistory.ModuleContract.ps1` 不在库中）。
- 本仓不用 Git LFS；`z-Publish/** binary` 让快照按原始字节入库，否则主树快照与自己的 `SHA256SUMS` 对不上。
