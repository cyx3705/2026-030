# HistoryApollo 项目概览

更新日期：2026-09-14

## 一句话定义

HistoryApollo 0.3.2 是注册到 HistoryVulcan 的模型调用模块：把 OpenAI 兼容的对话补全接口
变成宿主指令，首发支持 DeepSeek；0.2.0 起可按需联网搜索（博查）；0.3.0 起每一轮往返实时写进控制台。

## 目标与边界

### 目标

- 让宿主、CLI 与 MCP 消费方用一条指令完成一次模型调用，不必各自实现 HTTP 与密钥管理。
- 密钥只落在本机模块数据目录，回执、日志和结构化载荷一律只出现掩码。
- 换一家供应商只是改配置：接入点、模型和密钥在库里，协议共用 chat/completions。

### 范围

- 单轮提问（apollo.chat.ask）与完整消息数组的多轮调用（apollo.chat.send）。
- 供应商配置：默认供应商、默认模型、接入点、密钥读写。
- 模型清单查询。
- 按需联网搜索：`web=true` 时模块代模型调博查，搜不搜由模型决定（DEC-007）。

### 非目标

- 不保存对话历史。上下文由调用方持有并逐次回传。
- 不做提示词工程、结果解析、重试编排或并发调度。
- 不提供界面。本模块 ui=false，不依赖 Aurora。
- 不做逐字流式输出。回执仍是一次请求一次答复；0.3.0 起过程按轮实时进控制台（DEC-008）。

## 关键约束

- 平台或环境：Windows、.NET SDK 9、目标框架 net8.0；模块不依赖 Windows 专有 API。
- 兼容性：HistoryVulcan 5.1.2 冻结接入面（IModuleContext 只给 Bus 与 RegisterCommands）。
- 安全与权限：密钥不入库、不进回执；写密钥的参数名必须以 token 结尾，否则总线脱敏失效。
- 时间、成本或资源：每次调用都是计费的外网请求，因此 chat 指令不声明 Readonly；`web=true` 时另有按次计费的博查搜索。
