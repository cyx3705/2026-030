## 取舍

- **只做「一次调用」，不做会话。** 上下文由调用方持有并逐次回传；会随热重载消失的会话缓存只会让调用方以为不必管上下文。
  不做提示词工程、结果解析、自动重试（重试策略属于调用方，模块替它决定会掩盖计费与限流）。
- **联网搜索由模块代模型执行。** 搜不搜、搜什么由模型决定；`web` 默认关，打开后费用是 token 加按次计费的博查搜索两份。
  每次调用最多真搜 5 次，再宽限 2 轮仍只要工具就判卡住失败。单次搜索失败只告诉模型；博查没配密钥整次失败——那是配置问题，不该让模型装作查过。
- **调用过程归 Ratio 写进控制台。** 写 `CommandContext.Progress`，经总线的嵌套调用也有这条通道；消费方不要再从回执复述搜索与答复。
  粒度是「轮」不是逐字（`stream=false`）：控制台按行渲染，几路并发逐字刷屏反而读不清。
- **chat 指令不声明 Readonly。** 不写本机，但每次都是计费外网请求；标只读等于告诉「只读即安全」的消费面随便调。
- **密钥参数名必须叫 `token`、位置 0。** 总线按参数名判定敏感值，改成 `apikey` 会让回显、历史、结果脱敏同时静默失效（测试钉住）。
- **图片走识图供应商（0.5.0）。** 带 `images=` 且省略 `provider=` 时用识图供应商（内置 `qwen` 通义千问，`ratio.provider.use <名> vision=true` 可改），不用默认供应商。
  原因见下「真机才知道的」第一条。只收本机文件路径、不收网址（不替调用方多开出网口子）；超限直接拒、不偷偷缩图——缩到多小还看得清只有调用方知道。

- **本机推理服务归 Ratio，不再有单独的推理区（0.7.0，用户定）。** 源码在 `b-Code-Service/`，以嵌入资源随 DLL 发布，
  `ratio.local.start` 在服务没在跑时把它同步到运行区再启动——运行区的脚本只认已发布版本，别在运行区改脚本。
  运行区是 F 盘特例 `F:\ModuleServicesData\Ratio`（不进宿主 `ModuleData`）：KV 快照 40 GB 上限放不进 C 盘的模块数据区，原生 Ubuntu 也要能跑同一份；
  模型统一在 `F:\Models`。对话就是普通供应商 `local`（回环地址免密钥，不写默认模型——服务同一时间只装一个，调用时取它报出的那个）。
  换模给 Run（失败服务自己装回原模型），停服给 Ask（断所有客户端）。Sub2API 归 Juno 管，Echo 的专用接口（共享 KV、逐词概率）不在本模块。

## 真机才知道的

- **DeepSeek 收图片但看不到**（2026-10-06 实测 `deepseek-flash` 返回空、`deepseek-v4-pro` 回答「无法查看图片」，都是 HTTP 200）。
  不报错的「看不到」比报错危险：模型会照着文字瞎编，所以带图请求必须换供应商，而不是靠服务端拒绝。
- 服务端会把 `deepseek-chat` 解析成当次主推模型（实调返回 `deepseek-v4-flash`），回执按服务端返回的名字报告；要固定模型就显式传 `model=`。
- DeepSeek 思考模式下带工具的后续请求必须把助手消息（含 `reasoning_content` 与 `tool_calls`）**原样**回放，自己挑字段重建就是 400。
- 博查在 HTTP 200 里也会返回业务错误（`code != 200`），按远端失败处理，不当「没有结果」。

## 工程约定

- 发版改三处版本号：`RatioVersion.props`、`b-Code/Ratio/module.manifest.json`、`project.manifest.json`；`Test-ProjectContract.ps1` 核对一致。
- 数据目录由宿主给（`ModuleData\Ratio`）：`providers.json` 是供应商与密钥库、`logs\` 是日志；独立于包槽位，热装不抹密钥。
  环境变量优先：`RATIO_<供应商>_KEY` → `<供应商>_API_KEY` → 库文件，来源在 `ratio.provider.list` 里报告。
- 新增一家 OpenAI 兼容供应商：`ProviderStore.Builtin` 加一行，或本机 `ratio.provider.config provider=<名> baseurl=<地址>`。
- **密钥绝不入库**：合同检查扫全仓拒绝 `sk-` 后接 32 位以上十六进制；测试夹具写 `sk-fake…`、`sk-test`。
- 项目合同检查自带规则（共享的 `OneHistory.ModuleContract.ps1` 不在库中）。
- 本仓不用 Git LFS；`z-Publish/** binary` 让快照按原始字节入库，否则主树快照与自己的 `SHA256SUMS` 对不上。

## 推理原语（0.8.0）

给要逐 token 交互的消费方（Echo）用，替代它直连 11435 的私有 HTTP。只有供应商 `local` 有 `ratio.local.probs` 与 `ratio.seq.*`；`ratio.chat.stream` 任一 OpenAI 兼容供应商都行。Data 一律是 JSON 文本，字段只增不减：

- `ratio.local.probs` → `{"tokens":[{"token","logprob"}]}`（服务的 `/completion`，n_predict=1、temperature=0、cache_prompt）。
- `ratio.seq.caps` → 服务原样的能力对象（`supported`、`generation_streaming`、`backend`、`provider_parallel_slots`、`reason`…）；探测失败不报错，回 `supported=false` 与原因。
- `ratio.seq.open` → `{"sequence","epoch","prefixTokens"}`；`ratio.seq.choose` → 服务原样的一行结果（`label`、`decision_steps`、`shared_prefix_tokens`、`replayed_tokens`），旧服务没有 `select_text` 时自动拆成 prefix/tokenize/select 三步。
- 开流（`ratio.seq.stream`、`ratio.chat.stream`）→ `{"stream"}`；`ratio.stream.read` → `{"text","next","done","error"}`，`after` 传上次的 `next`（字符位置），读到 `done` 的那次后流即删除；闲置 90 秒的流自动取消，上游请求随之断开；同时最多 32 路。服务没有 `op=stream` 时退回逐步 `next`。
- 共享 KV 被服务拒绝时失败回执是 `shared_kv:<原因码>`（如 `shared_kv:invalid_sequence_size`），调用方按原因码决定是否退回普通对话。
- 模块卸载时把还开着的序列逐个释放。

## 向量（0.9.0）

- `ratio.embed.texts texts=<JSON 字符串数组>` → Data `{"provider","model","dimensions","vectors":[[…]],"usage":{"totalTokens"},"elapsedMs"}`，向量按输入顺序；正文不放向量。
- 默认通义千问 `text-embedding-v4`（DeepSeek 没有向量接口，本机服务同一时间只装一个对话模型）；别家要写 `model=`。
- 每批 10 条顺序发（通义硬限），任一批失败整次失败，不回半截。一次最多 500 条、每条 2000 字。
- 只做一次调用：不建索引、不存向量、不算相似度——语料与缓存失效规则归调用方（Diana 能力地图、Usus）。
- `ratio.chat.ask/send` 加了 `schema=`（json_schema strict）与 `think=false`（`chat_template_kwargs.enable_thinking=false`）。
