# LinuxModuleServices

## Continuous KV generation and maintenance scheduling (ECHO-KV-004, 2026-10-28)

`/v1/kv/op` advertises `generation_streaming=true`. `op=stream` with the existing A lease and `max_tokens` (1..8192) streams deltas on one SSE connection, submitting each A step locally at the front of the same model queue. Each step owns a fresh response reader. B suffix prefill still yields in 64-token slices; completion or cancellation frees B immediately. A remains caller-owned until release, including after EOS or disconnect. Limits do not generate a spare token. Success requires `done:true` followed by `[DONE]`; errors and truncated responses are not successful completion. Older clients retain `next`/`finish` compatibility.

Snapshots check all public slots and native leases, then recheck admission atomically inside the model queue for both save and restore. `model_busy_for_snapshot` defers maintenance without replacing a good disk copy. This closes the previous slot-0-only check and the probe/execution race; it does not prove that any specific historical multi-second pause came from a snapshot. Both public slots 0/1 and reserved A/B IDs 2/3 use one model context; earlier one-slot descriptions below are historical.

From Windows, use Echo's virtualenv Python and its existing dictionary/data environment to run `scripts/echo-kv/bench_scheduler.py --live --rounds 3 --tokens 64 --out status/echo-scheduler-after.json` and `scripts/echo-kv/verify_scheduler.py --live --out status/echo-scheduler-stream-checks.json`. These scripts import Echo's actual prompt builder, use the current model only, and never write its user database. The benchmark alternates native SSE, per-token KV HTTP and persistent KV SSE with/without eight 242-token sense suffixes, recording output hashes and token-gap distributions. Linux HTTP microbenchmarks from ECHO-SVC-003 below are not Windows continuous-output measurements.

Three alternating Windows-side 8B rounds with the identical prompt and 64 generated tokens produced the same output hash on every path. Median steady output: native completion 63.5 token/s; per-token KV HTTP via C++ 13.8; persistent KV SSE via C++ 65.2. With eight 242-token B suffixes, per-token HTTP yielded 15.2 versus persistent SSE 31.7 token/s. Median per-trial token-gap P95 fell from 92.0 to 61.6ms (16.5ms without B). B response median increased from 146.1 to 191.6ms while A gets priority; translation still costs GPU time. These short-context 8B results do not establish other-model or competing-client performance. Live limit/EOS/disconnect/B-reclamation/snapshot-admission checks and source-state isolation passed, ending with zero A/B/checkpoint state and equal fork/release counts. Echo isolated application acceptance passed all eight checks, short chat with glosses 1.55s. Offline tests: Echo 85, service control/cache/legacy proxy 47, compiled proxy/migration 14; UI queue/input/model menu passed.

## C++ HTTP entry (ECHO-SVC-003, 2026-10-28)

The active listener on 11435 is now `linux-cache/echo-kv-build/build/echo-proxy`, built from `scripts/echo-kv/echo-proxy.cpp` using the pinned upstream cpp-httplib and nlohmann sources. There is no resident Python HTTP proxy. Chat, raw completion/probabilities, shared-KV operations and SSE use C++ throughout the service request path, with one existing llama-server/model on 18769. Echo's business application remains Python. Low-frequency model-control workers and the KV disk-cache watcher still use the existing Python scripts.

The C++ entry preserves upstream status/error bodies and query strings, bounded incremental SSE, cancellation before headers and during streams, the model management API, switching admission and per-model shared-KV policy. Echo requests pass through without per-request template rendering, tokenization or disk snapshot alignment. Model-owned prompt/RAM caching, periodic snapshots and startup restore remain active. OpenClaw temporal system-tail and tool-delta adaptation is retained in C++; Echo requests are exempt. Old proxy text-prefix accounting and per-request metrics files are no longer updated; `/cache/stats` explicitly reports the C++ backend, disabled request-time disk alignment and the current disk-watcher status. The Python-specific cache-alignment, metrics and idle-wakeup descriptions below are historical, not promises of the new listener.

## Echo 接入（ECHO-SVC-001/002，2026-10-28）

Echo 和其他客户端共用 11435 代理与单模型两槽服务，不启动第二个模型实例。Echo 以 `X-Local-AI-Client: echo` 标识流量，该标记仅用于统计，不能授予权限。Echo 的 A 生成与短暂 B 选义在同一模型上下文中交错，B 完成后立即释放；槽位仍有界，不能把两槽理解为两份模型权重。

- `GET /v1/echo/capabilities`：只读探测上游共享 KV 元数据，不执行预填或生成；只有全部原语可用才声明原生分叉。
- `POST /v1/chat/completions`：提供普通 SSE/JSON Schema 接口，保留既有 OpenClaw/Codex 适配。支持共享 KV 的 Echo 使用下方原生路径生成回复和受限选义，标题与兼容服务仍走普通接口。
- `POST /completion`：原始用户回合提示的下一词概率；透传 `n_predict=1`、`n_probs=20` 和原始 token 概率，绝不再套 chat 模板；尊重显式 `cache_prompt=false`。
- 原始预测也参与已有磁盘分支匹配和真实缓存使用统计。只记录字符数、token 计数和耗时，不记录提示、预测候选、生成内容或密钥。短输入/缓存收益不足时不保证磁盘恢复；共享服务仍可能排队。
- SSE 与非流式请求均从等待响应头阶段开始监测客户端断开，断开即关闭上游连接，取消排队/预填/生成。模型实际回收速度取决于其调度，不能用“代理已关闭连接”替代模型端验证。

部署代理代码后可运行 `bash scripts/wsl-model-service.sh restart-proxy`，只重启代理，不重载模型、不调整显存、槽数或服务模型。完整 `stop` 仍先保存模型缓存。源码回退副本在 `archive/echo-service-adapter-` 开头的对应目录。

离线验收：`cd scripts && python3 -m unittest test_local_ai_cache_proxy test_kv_disk_cache`。Echo 仓库的 manifest `testExternalLive` 使用临时学习/对话库访问实际服务，验证状态、预测、整词翻译、银行语境选义、流式对话保存和标题，不写现有 Echo 学习数据。最近真实结果见 `status/echo-acceptance.json`（仅成功完成后生成）。

第一阶段历史验收：服务端离线测试37项、Echo业务回归66项通过。`status/echo-acceptance.json` 记录8个真实检查全部通过：状态、3次预测（含相同提示/半词排名复用）、整词翻译、网页银行选义、流式对话保存和标题。首预测约2.6秒，排名复用2～4毫秒，网页批量选义约8.4秒，短对话含选义约27.9秒；均为单次样例，不是性能分布。`status/echo-cancellation.json` 记录当时非流式请求在响应头前断开后，模型任务约919毫秒释放。

现场发现后台快照保存可持有 `operation.lock` 等待模型空闲；请求侧 `align_request` 已改为非阻塞锁，忙时跳过恢复，避免缓存匹配把预测卡在队列之外。第一阶段部署只重启代理，当时没有精确位置 KV 分叉；后续服务升级已按下方实现。

## 共享 KV 分叉（ECHO-KV-001/002，2026-10-28）

当前 `/v1/kv/op` 与普通请求进入同一 llama-server 推理队列，使用一份权重和一个上下文。公共槽仍为 0，另外预留序列 1（A）和 2（B），不增加第二个模型进程。Echo 仅持有外部句柄，不构建或启停服务。接口支持能力/运行状态、分词、创建 A、定位前缀、分叉、单 token 标签选择、A 续写和释放；epoch 与句柄必须匹配。

Qwen3.5 是注意力/循环混合模型，单独 `seq_cp` 不能保证历史位置的循环状态。扩展共享检查点之前的注意力 KV，同时恢复该位置的循环状态，再仅重放检查点到目标之间的 A token。分别报告 `shared_prefix_tokens` 和 `replayed_tokens`，不把重放计作共享。聊天选义只分叉目标实际左侧的前缀；网页/字幕选义允许读取完整段落。

当前一次租用一个 A、一个顺序执行的 B；A 最多 8192 token，B 后缀最多 2048 token，每次选择最多 12 个目标。最多保留 8 份循环检查点，每份上限 80 MiB；预填间隔 256 token、生成间隔 32 token。错误和正常完成回收 B；取消在批次之间检查，创建取消回收迟到句柄，只读请求断开不释放其他请求的 A；90 秒未使用的 A 在后续模型队列任务中回收。标签必须各自恰为一个 token（当前 Qwen 的 `0` 不加前导空格）。双 B 同批、页面 A 跨请求持久复用尚未实现；公共请求仍可能竞争队列和统一 KV 空间。

权威扩展源码在 `scripts/echo-kv/`；`linux-cache/echo-kv-build/` 是可重新生成的上游源码与二进制。构建使用 WSL GNU C++/CMake，只重建 server 层，链接已有 libllama/ggml/CUDA。固定上游提交 `9ff0d7e90f0faaa7c16017e6dcf9cf91c50a100e`，归档 SHA256 `d8552e1b309c1571e49baf7a53d429b9709fa0c1d6907c446f6cecb87087d07b`，下载后先校验再构建：

```bash
bash scripts/echo-kv/build.sh
python3 -m unittest discover -s scripts/echo-kv -q
python3 scripts/verify_echo_shared_kv.py --live --out status/echo-shared-kv.json
```

重建完成后需完整重启模型才能启用，`restart-proxy` 不能更新 server。显式升级先停止代理和后台快照 watcher、排空调用，再运行 `python3 scripts/echo-kv/migrate_cache.py prepare`，随后使用生命周期脚本 `stop` / `start`。启动会在开放代理之前 `apply`：校验模型、模板、上下文、除可执行文件以外的全部启动参数、共享库和快照摘要，恢复公共槽并登记新快照；原快照保留，普通兼容检查不放宽。首次升级恢复 11,157 token（`status/echo-kv-cache-upgraded-initial.json`），取消边界修正后再次重启恢复 12,042 token，见 `status/echo-kv-cache-upgraded.json`。

当前验收：服务回归 38 项、升级保护 3 项、Echo 回归 72 项通过。`status/echo-shared-kv.json` 验证历史位置实际共享 256 token、重放 72 token，恢复的循环状态载荷逐字节相等、B 执行前后 A 完整状态逐字节相等，7 次分叉全部回收；30 次元数据请求断开后原 A 仍可用，预填中取消也没有遗留 A。不同批次/序列的 Q8/MoE logits 存在数值差异，报告保留实测误差，不保证逐位一致。

`status/echo-shared-acceptance.json` 记录修正版真实业务 8 项通过，使用临时用户库；运行结束累计 20 次分叉/20 次释放，A/B 和检查点均为零。首预测约 1.9 秒、排名复用 1～3 毫秒、整词翻译约 4.3 秒、网页银行选义约 11.3 秒、短对话含选义约 44.8 秒。共享服务存在竞争，这些仅是单次样例；网页/短对话没有快于第一阶段 JSON 路径，不声称性能提升。新 server 的普通非流式请求取消复验约 840 毫秒释放，见 `status/echo-shared-cancellation.json`。

## 更换模型（ECHO-MODEL-001，2026-10-28）

Echo 顶栏「更换模型」通过统一服务 HTTP 管理协议执行真实切换。`GET /v1/echo/models` 提供已登记模型、完整下载检查、不可用原因和当前任务；`POST /v1/echo/model` 接受模型名称、返回任务；`GET /v1/echo/model` 查询阶段与结果。POST 只接受本机应用的 JSON 请求、拒绝浏览器 Origin；Echo 自身的模型接口仍只允许本机访问。普通 OpenAI 协议和原端口不变。

服务配置位于 `config/echo-models.json`，模型权重仍由现有 Ollama manifest 定位，校验完整文件长度及 GGUF 标识。当前启用 35B、Qwen3 8B（32k）和 Gemma4 12B（16k），27B 尚未配置显存方案，明确禁用；不下载权重、不接受用户传入路径或启动命令。`scripts/fast-path-35b.sh` 保留统一环境，委托 `scripts/model_switch.py launch` 按选中配置启动同一个扩展 server。

切换会影响所有共用客户端。11435 代理保留运行，拒绝新的推理请求（503），继续提供管理状态并允许 A/B 释放。独立 worker 持有文件互斥锁，等待既有公共推理与共享租用结束，保存原公共槽缓存，确认旧进程退出后才加载新模型；恢复只使用原有模型/运行参数兼容检查。成功后持久化选择，失败则尝试恢复原模型与缓存，恢复失败明确报告。新客户端在加载期间应退避；代理重启不会终止切换 worker。无需通过 Echo 启动/停止任何进程。

Gemma4 tokenizer 自动插入 BOS，该真实 token 占一个位置但对应原提示零字节；显式 BOS 只保留一份。服务定位前缀时保留该位置，其他提示字节仍须完全一致。但 Gemma4 滑动窗口检查点尚未通过共享状态校验，当前配置 `shared_kv:false`：公共接口明确报告不支持原生分叉并拒绝分叉操作，Echo 使用普通对话、概率预测及 JSON Schema 选义。Qwen3 8B 与 35B 使用已验证的共享 KV 路径；不因 Gemma4 能建序列就声称它的分叉已适配。

```bash
python3 -m unittest discover -s scripts -p 'test_model_switch.py' -v
```
